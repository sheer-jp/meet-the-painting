# 作品の登録（管理画面から、会話で）設計

11-08 作家「管理画面から絵をアップロードすると API が動いて登録できるといい。チャット形式くらいで登録したい」。この文書は設計で、まだ作っていない。決めてほしいことは 9 節。

## 1. いまの登録と、変えるところ

いまは、作家（か Claude Code）が次を手で行っている。

1. `works/<id>/painting.jpg` と `work.json` を置く（`docs/WORK_FORMAT.md`）
2. `npm run generate -- <id>`：流れ場、主要色、部屋の合成、QR、翻訳、物語の下書き、作品ページ
3. `npm run build` → 確認 → `wrangler pages deploy` → Git に上げる

2 は `sharp`（画像処理の部品）を使い、数分かかる。Cloudflare の Functions の中では動かない。そこで「会話で下書きを作る」ところは Cloudflare に置き、「生成して公開する」ところは別の場所で動かす、の 2 段に分ける。

## 2. 全体の流れ

```
作家（管理画面「作品を登録」）
  │ 写真を選ぶ → 会話で項目を埋める → 確認カード → 「公開する」
  ▼
Cloudflare Pages Functions（/api/admin/works/*）
  │ 写真は R2、下書きは D1（work_drafts）。会話は Claude API（文だけ。写真は送らない）
  │ 「公開する」で GitHub Actions を呼ぶ（方式 A）／ Mac の 1 コマンドが拾う（方式 B）
  ▼
公開の作業（GitHub Actions の publish-work、または Mac の scripts/publish-draft.mjs。中身は同じスクリプト）
  │ 下書きと写真を取りに来る → works/<id>/ を書く → generate → 単体テスト → build → 軽い確認
  │ → main にコミット → wrangler pages deploy → 結果を API に返す
  ▼
管理画面に「公開しました」とページの URL、部屋の合成、QR、展示用キャプションが出る
```

## 3. 会話（登録の聞き役）

受付の案内役とは別の、作家のための聞き役。口調は短く、1 回に 1 つだけ聞く。答えにくいものは「あとで」で飛ばせる。

| 順 | 聞くこと | 埋まる項目 | 確かめること |
| --- | --- | --- | --- |
| 1 | 写真を選んでください | `painting.jpg` | 長辺 1600px 以上、JPEG／PNG／HEIC、15MB まで。ブラウザで長辺 2000px に縮めてから送る。90 度回転だけその場で直せる |
| 2 | この絵の名前は？ 英語の名前もあれば | `title.ja`、`title.en` | 空なら先に進まない。英語は任意（無ければ訳） |
| 3 | 描いた年は？ | `year` | 4 桁の数 |
| 4 | 大きさは？（号でも cm でも） | `size_cm`、号の表示 | 「F15」なら 65.2 × 53.0、縦横は写真の向きから決める。写真の縦横比と 5% 以上違えば「写真の端が切れていませんか」と聞き直す |
| 5 | 何に描きましたか？ | `medium.ja`（`en` は訳） | 例を 3 つ出す（キャンバスにアクリル、シナベニヤにミクストメディア…） |
| 6 | 値段と、いま買える状態か | `buy.price_jpy`、`availability` | 税込の円。「売れた」「非売品」も選べる |
| 7 | Stripe の支払いリンク（あれば） | `buy.url` | `https://buy.stripe.com/` で始まるかだけ確かめる。「あとで」可 |
| 8 | この絵に込めた想いを、話すように教えてください | `messages`（3〜10 文、1 文 40 字以内）の下書き | 作家の言葉から聞き役が文を整えて並べる。**作家の言葉に無いことは足さない**。並べた文を作家が直して「これでいい」を押すまで確定しない |
| 9 | どんな気分の人に見てほしいですか | `moods.ja`（3〜5 語）、`moods.fit` | 受付の案内役がおすすめの手がかりにする。下書きを出して作家が選ぶ |
| 10 | 確認カード | すべて | 作品ページの見え方、展示用キャプション、寸法、値段を 1 枚で見せる。「直す」で該当の質問へ戻る |

- 聞き役は Claude API の tool use で、項目ごとの道具（`set_title`、`set_size` …）だけを呼べる。道具の入力は型で縛り、サーバー側でもう一度確かめる。会話の文から事実（年、寸法、値段）を推測して埋めない。作家が言ったことだけを入れる
- 写真は Claude に送らない（CLAUDE.md「作家の絵の画像を生成モデルに入れない」）。気分の言葉の下書きに色を使いたいときは、ブラウザで写真から主要色を数色取り、色の値（#c23a2b など）だけを文として渡す
- 部屋は大きさから自動で選ぶ（`rooms/*.json` の `suits_cm`）。作家は選び直せる
- 物語（小さな物語）は今どおり生成で下書きし、作家が管理画面で読んで「公開する」を押すまで出さない（`story_approved`）
- 会話の途中で閉じても、下書きは D1 に残る。次に開くと続きから

## 4. 保存するもの

| 置き場 | 中身 | 消すとき |
| --- | --- | --- |
| R2（新しく足す。`WORK_UPLOADS`） | 下書きの写真（縮めたもの） | 公開して Git に入ったら 30 日後、下書きを捨てたらすぐ |
| D1 `work_drafts`（新しい表） | id、状態（draft／queued／building／published／failed）、work.json の中身（JSON）、写真の鍵、作った日時、公開の記録（コミット、デプロイ、失敗したときの最後の 40 行） | 公開して 90 日後に記録だけ残して中身を消す |

会話の文は保存しない（今の方針どおり）。保存するのは項目の値と、確定した文だけ。

## 5. 公開の 2 つの方式

| | A：GitHub Actions で自動 | B：Mac で 1 コマンド |
| --- | --- | --- |
| 作家の操作 | 管理画面の「公開する」だけ | 「公開する」のあと、Mac で `npm run publish-drafts` |
| どこでも | スマホからでも公開できる | Mac が要る |
| 時間 | 5〜8 分 | 3〜5 分 |
| 用意 | ワークフローの追加（GitHub Actions 課金ガードレールにより作家の承認事項）。repo は public なので標準のランナーは無料。GitHub 側に `CLOUDFLARE_API_TOKEN`（Pages の編集だけの権限）と `ANTHROPIC_API_KEY`、Cloudflare 側に GitHub を呼ぶトークン（このリポジトリの workflow の起動だけ） | 追加の鍵は要らない |
| 失敗したとき | 管理画面に失敗と最後の 40 行。下書きは残るので、直して「もう一度」 | ターミナルに出る |

おすすめは **B で作り始めて、動きが固まったら A を足す**。中身は同じ `scripts/publish-draft.mjs` で、A はそれを Actions から呼ぶだけ。

`publish-draft.mjs` がすること：下書きと写真を取得（管理用の API を、公開専用のトークンで読む）→ `works/<id>/` を書く → `generate -- <id>` → 単体テスト → build → 作品ページと部屋の帯が開くかの軽い確認 → main にコミット（`works/<id>/` だけをパス指定）→ deploy → API に結果を返す。どこかで失敗したら、コミットもデプロイもしない。

## 6. 管理画面の見え方

- ダッシュボードの上に「作品を登録」と「作品の一覧」のタブを足す
- 「作品を登録」：左に会話、右に確認カード（スマホは会話の下にカード）。項目が埋まるたびにカードが育つ
- 公開中は「生成しています（部屋の合成、翻訳…）」の段階を出す。終わったら作品ページ、部屋の合成、QR、展示用キャプションへのリンク
- 「作品の一覧」：今の作品と下書き。直す（同じ会話を、今の値を入れた状態で始める）、売れた（`availability` を変える。再生成の要らない変更は D1 に持って、実行時に上書きする形にすると数秒で反映できる。11 節）

## 7. 安全

- 管理の認証（ID とパスワード、HMAC の Cookie、同じ origin からの書き込みだけ）をそのまま使う
- 写真：種類を中身で確かめる（拡張子を信じない）、15MB まで、EXIF の位置情報を消す
- id（URL になる）は英語の題名から作り、作家が確認する。今の作品と重なれば番号を付ける
- 公開専用のトークンは、下書きを読む・結果を書く、の 2 つしかできない
- 公開は 1 件ずつ（同時に 2 つ走らせない）。1 日の上限を置く（Claude API の使いすぎと、Actions の回しすぎを防ぐ）
- 戻すとき：その作品のコミットを revert して配置し直す

## 8. 作る順（目安）

| 段 | 中身 | できること |
| --- | --- | --- |
| R1 | D1 の表、R2、写真のアップロード、会話（項目の道具）、確認カード、下書きの保存 | 管理画面で下書きまで作れる |
| R2 | `scripts/publish-draft.mjs`（方式 B） | Mac の 1 コマンドで公開できる |
| R3 | 作品の一覧、直す、売れた（再生成なし） | 登録後の手入れが管理画面で済む |
| R4 | GitHub Actions（方式 A）、進み具合の表示 | スマホから公開まで完結 |
| R5 | 物語の確認と公開、英語の文の確認 | 文の仕上げも管理画面で |

R1 と R2 で、作家の手元の作業は「写真を撮る → 会話 → Mac で 1 コマンド」になる。

## 9. 作家に決めてほしいこと

1. 公開の方式：B から始めて A を足す（おすすめ）か、最初から A か
2. 写真を Claude に見せるか：見せない（おすすめ、今の決まりどおり。色の値だけ渡す）か、気分の言葉の下書きのために見せるか
3. 想いの文：作家が話した言葉を聞き役が 3〜10 文に整える形でよいか（整えた文は必ず作家が確定する）
4. Stripe の支払いリンク：今どおり作家が Stripe で作って貼るか、登録の中で作る（Stripe の鍵を Cloudflare に置くことになる）か
5. 公開前の確認：毎回、確認カードで「公開する」を押す（おすすめ）か、下書きを保存したら自動で公開するか

## 10. 費用の目安

- Claude API：登録 1 件で会話 20 往復ほど、Sonnet 5.5 で数円〜十数円。翻訳と物語の下書き（generate）で数十円
- R2：写真 1 枚 1〜2MB。無料枠の中
- GitHub Actions（方式 A）：public repo の標準ランナーは無料。1 回 5〜8 分

## 11. 再生成の要らない変更

売れた・値段・Stripe のリンクのように、作品ページの見た目や流体に関わらない値は、D1 の `work_overrides` に持ち、実行時に `/api/works-status` と同じ形で上書きする。これなら公開の作業を通さず、数秒で反映できる（今の sheerarts.com の中継とどちらを正にするかは R3 で決める）。
