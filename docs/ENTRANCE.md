## 1. 誰のどの悩みに効くか（`docs/USERS.md`）

- **E オンラインで絵を見る人**：絵が並んでいても、どれが自分の絵かわからない。先に「自分のこと」を話してから絵に会うと、出てきた 1 点が「自分のためにある」と感じやすい（仮説 10）
- **B 来場者**：会場では作家が「どんな絵をお探しですか」と聞いてくれる。その接客をオンラインの最初に置く
- 受付を**先に**置く理由：人は「見せられた絵」より「自分の言葉のあとに出てきた絵」に心が動く。だから会話のあとに絵が現れる順番にする

仮説 11：受付の会話を通った人は、一覧から選んだ人より、絵の中に入ったあとの「買いたい」（1〜5）が高い。検証：`?via=concierge` と `?via=gallery` で入口を分け、体験後の 1 問で比べる。

## 3. C 受付の画面

### 3.1 構成（スマホが基準。PC はその拡大）

```
┌─────────────────────────┐
│ ようこそ、SHEER のギャラリーへ   │ 見出し。明朝、小さく。英語は Welcome to SHEER's gallery。右上に言語
│                           │
│   [キャラクター 上半身]        │ 上。高さは画面の 32〜38%（スマホ縦）。紙の白。名前は小さく下に（空なら出さない）
│                           │
├─────────────────────────┤
│ 〔いらっしゃいませ。〕          │ 会話。キャラクターの文は左に吹き出し、自分の文は右。1 吹き出しずつ
│ 〔今日は、どんな絵をお探しですか？〕│
│                           │
│   ┌ 朝、静かに始めたい ┐       │ 3 つの選択肢（縦積み、タップ）。打ち始めたら消える
│   ┌ 夜、ひとりで息をつきたい ┐  │
│   ┌ 人を迎える部屋に彩りを ┐   │
├─────────────────────────┤
│ [ こんな気分のときに、こうしたい ] [送る] │ 入力欄。画面の下に固定。キーボードで会話が隠れない
└─────────────────────────┘
```

- **最初の 2 文は固定**（`recommend/config.json` の `greeting`）。API を待たず、0.4 秒ずつ間を置いて現れる
- **最初の画面はボタンだけ**（11-06 夜、作家「ボタン形式だけのほうがすっきり」）：3 つの選択肢（`openers`：「頑張る活力がほしい」「寂しい夜に寄り添ってほしい」「明るい気持ちになれる絵を」）＋ 4 つ目「自分のことばで書く」。上に案内の一行「近いものがあれば、選んでください」。4 つ目を押すと選択肢が消えて入力欄が現れ、自動でフォーカス。2 往復目以降は AI の問いに自由文で答える（入力欄あり）。選択肢は吹き出しと見分けがつくボタン（左寄せ、白地、角は小さく、右端に ›）
- **1 吹き出しずつ**。ストリーミングの文字はそのまま流す。文が来るまで「…」の 3 点をゆっくり明滅
- **表情**：3 枚の画像を切り替える。`listening`（相手が打っている・AI が考えている）、`smile`（AI の文が出ている）、`present`（おすすめを差し出した）。切り替えは 300ms のクロスフェード。`prefers-reduced-motion` では即時
- **往復は 2〜3 回**（`recommend/config.json` の `turns` は `[2, 3]`。11-06 作家「やりすぎず、少なすぎず」）
- **おすすめ**：AI の最後の文のあと、会話の中に**絵のカード**が現れる（初めて絵が出る瞬間。3.4 の演出）。見出し「今日のあなたへの 1 点」。カード：絵（実寸比）、題名、寸法、理由の 1 文、使ったことば（5 節の `matched_moods`）を小さく。選択は 3 つ（縦、44px）：
  1. 主：**「この絵の中に入る」** → 作品ページ `/w/<id>/?via=concierge`（そこで「入る」）
  2. **「別のにする」** → `alt` があれば alt のカードに差し替え（「では、こちらはどうでしょう」の 1 吹き出し。API は呼ばない）。alt が無い・2 回目なら AI に「別の絵を」の 1 往復（上限を 1 回だけ超えてよい）。ルールだけの版は 2 番目に近い作品
  3. **「ギャラリー全体を見る」** → `/gallery/?from=<id>`
- **作品ページ（S0）の帯**：`?via=concierge` で着いたとき、絵の下・「入る」の上に細い帯「今日のあなたへの 1 点」＋ 小さく「別のにする」（`/?retry=<id>`。受付に戻り、キャラクターが「別の絵を考えますね」と言ってから alt か再提案）と「ギャラリー全体を見る」。直前のおすすめは `sessionStorage` に持つ。`via` が無ければ帯は出さない
- **終わったあと**：カードの下に小さく「もう一度、話す」。押すと会話が消えて最初に戻る
- **API が無い・失敗・拒否**：ルールだけの版（3 問の選択肢）を**同じ画面・同じキャラクター**で出す。見た目は変えない。失敗したことは言わない（「少し考えさせてください」程度）
- **合言葉（実験のあいだ）**：Function 側の `env.PASSPHRASE` が空でないとき、ブラウザは最初の送信の前に 1 回だけ「合言葉」を聞く（キャラクターが「ここは準備中の部屋なので、合言葉をいただけますか」）。入力は `X-Passphrase` ヘッダで API に添え、Function が比べて違えば 403。一致したら `localStorage` に覚える。違えば（または合言葉を持たなければ）ルールだけの版で会話する。ブラウザのコードに合言葉を置かない。合言葉が要るかどうかは、ページ読み込み時に `GET /api/recommend/config`（`{ passphrase: true|false }` だけ返す）で知る。`PASSPHRASE` は Pages の Secret。空なら照合しない
- 言語は端末の言語（既存の判定）。キャラクターの文は作家の言葉のトーン（説明しない、売り込まない、情景で話す）。会話は保存しない。名前や連絡先は聞かない

### 3.2 スマホの要件

- **二つの状態**（11-06 夜、作家）：**迎え**（最初の画面）はキャラクターが上に（縦で高さの 30%。作家「人がデカすぎる。チャットの UI に」）、あいさつと 4 つのボタン。**会話**（最初の選択から）はキャラクターを 15% に縮め（0.4 秒）、会話の欄を広く。キーボードが出たら 12%。吹き出しの本文は 16px・行間 1.75
- **PC も同じ**（作家「パソコンでも同じ感じで」）：上に人、下に会話のゲーム風の縦 1 列。幅 640px で中央、人の高さは 220px（会話では 150px、キーボード 120px）で固定（画面が高くても大きくしない）。左右 2 列の配置はやめた。どの画面も上半身の画像
- **色**（11-06 深夜、作家「白黒をはっきり」「背景はしっかり白」「絵の外ににじむ色は要らない」）：背景は #ffffff、インクは #141210、線は rgba(20,18,16,.22)。作品ページも同じ白で、絵の周りの色の光は出さない。作品ページとの整合は「同じ紙と同じインク」で取る
- **あいさつは 3 文**（作家の案）：「ようこそ、SHEER のギャラリーへ。」「彩り美しい抽象画の世界を届けます。」「今日は、どんな絵を探してる？」。見出しは英語で「SHEER Gallery」。迎えの状態は会話を上に詰めて、窓との空白を作らない
- 縦 375×667（iPhone SE）の会話の状態で、キャラクター・最新の 2 吹き出し・入力欄が同時に見える。キーボードが出たら会話が入力欄の上に詰まり、最新の吹き出しが見える（`visualViewport` で高さを追う）
- 横向きでは、キャラクターを左 36%、会話を右に
- タップの的は 44px 以上。送信は Enter（PC）とボタン（スマホ）。`enterkeyhint="send"`。iOS で入力欄に寄ると拡大しないよう `font-size` は 16px 以上
- フォントの拡大（iOS の文字サイズ）で崩れない。`100dvh` を使い、`100vh` は使わない。`viewport-fit=cover` と `env(safe-area-inset-*)`
- 画像は `public/concierge/*.png` を 2 枚ずつ（1x 512px、2x 1024px）。`<picture>` で出し分け。合計 600KB 以下
- 受付のページ用 JS は gzip 27KB 以下（11-06 深夜：`page.js` 17KB + 受付の chunk 9KB = 26.2KB。最初に読むのは `page.js` だけ）。体験バンドルは読まない

### 3.3 キャラクター（11-06 夜の判断を反映）

- **決定（11-06 夜）：女の子（`public/concierge/artist/`）に確定**。作家「女の子のキャラのほうがかわいい」。猫（`concept/concierge-cat-v2/`）は比較用として概念フォルダに残し、サイトからは外す。`?chara=` の切り替えも外す（U-12 済）
- **画像**：全身の透過 PNG が元（女の子は 11-07 から第 6 案 `concept/concierge-v6/cutouts/`：パキッとした線のポップな絵柄、白いワンピースに鮮やかな絵の具。第 5 案は水彩のタッチ。猫は `concept/concierge-cat-v2/cutouts/`）。**窓の背景**（`public/concierge/wall/wall-wide|tall`、`.cg-host::before`）：キャラクターと同じ世界観のイラストの「絵のあるギャラリーカフェ」（白い壁、大きな観葉植物、木のカウンター、照明。Codex 生成）。壁の絵は実物の写真を sharp で合成し、この背景に限って実寸より 1.5〜1.8 倍大きめに掛ける（DECISIONS 61）。背景は Mac の Vision で抜く（カップルウィッシュリストの `character-cutout.swift`）
- **上半身版は切り出し**（生成し直さない）：全身から上 58%・横中央 72% を `*-bust.png`。スマホ縦と PC の通常は bust、横向き・幅 900px 以上は full を縦いっぱい。1x 512 / 2x 1024、`scripts/concierge-assets.mjs` で作る
- **ポーズ**：`listening` ← 聞く、`smile` ← 手を合わせる、`present` ← 手を上げる。切り替えは 300ms クロスフェード
- **動き**：CSS の呼吸（±2px、scale 1.00〜1.012、4.5 秒）は常に。コマがあれば `frames.json` のコマ列で `blink`（聞いているあいだ 4〜7 秒おき）、`wave`（差し出した直後に 1 回）、`smileDeep`。1 コマ 120ms。コマは確定した 3 枚と同じ構図で Codex に生成（`concept/*-frames/`）。揺れが目立つコマは使わない。`prefers-reduced-motion` では呼吸もコマも止める
- **動きのパターン（11-07 A-1、作家「もっとアニメーションっぽく」）**：コマを 8 枚追加（`nod-1/2`、`tilt-1/2`、`think-1/2`、`happy-1/2`。Codex 生成、`concept/concierge-v6-frames/`）。元は 1254×1254 で、既存の cutouts と同じ大きさだった。`smile`（`01-welcome-hands`）の足元（下端と下 100 行の重心）に**整数の平行移動**（0〜3px）で合わせて `concept/concierge-v6/cutouts/` に置いた。拡縮はしない（頭の幅の差 0.2〜1.4% はかしげ・うなずきの形の差、足の幅も 1% 前後）。合わせたあとのずれは横 0.4px・縦 0px（0.03% 以内）。`happy-2` は「少し跳ねる」コマなので上下はそのまま（14px 上、1.1%）。新しいコマは内側の不透明度が 240〜254 にゆらいでいたので 255 にそろえた（輪郭の半透明はそのまま）
  - **新しいコマの手は `smile`（胸の前で合わせる）と同じ形**。`listening`（手は下）・`present`（手を上げる）から入ると、手が 1 コマで跳ぶ。そこでコマ列の中の表情の名前（`listening` / `smile` / `present`）は「いまの表情の止まっているコマ」に置き換えて再生する（`smile` のあいだは `smile` か `smile-2` から入る＝跳ばない）
  - **11-07 A-2：手の位置を合わせたコマ**（6 枚。Codex 生成、`concept/concierge-v6-frames2/`）：`nod-down-1/2`・`tilt-down-1/2`（`listening` の姿勢＝手を下で組んだまま）、`happy-up-1/2`（`present` の姿勢＝片手を上げたまま）。A-1 と同じ方法で `listening`（`03-listening`）／`present`（`02-welcome-wave`）の足元に整数の平行移動で合わせた（横 0px・縦 0〜2px。合わせたあとの重心のずれは 0.5px 以内。`happy-up-2` は跳ねるコマなので縦は `happy-up-1` と同じだけ動かし、跳ねた 20px はそのまま）。内側の不透明度（240〜254）は 255 に。手・腕の帯（下 30%）の差は `listening` → `nod-down` で 6.5〜7.3（旧 `nod` は 23〜25）、`present` → `happy-up-1` で 5.8（旧 `happy-1` は 18.6）
  - **いまの表情に合う列を選ぶ**（`index.ts` の `MOTION`）：`smile` → `nod` / `tilt` / `tilt2`、`listening` → `nod-down` / `tilt-down` / `tilt-down2`、`present` → `happy-up` → `wave`。合う列が無い表情では動かさない（手が跳ぶので）。C2 の「別のにする」は、`present` のかしげのコマが無いので `happy-up` を 1 回
  - **コマ列**（`frames.json`。形は `["a", "b"]`（1 コマ 120ms）か `{ "seq": [...], "ms": 160 | [120, 800, 120] }`。ページはどちらも読む。`src/concierge/index.ts` の `parseFrameDef`）：
    - `nod`：smile → nod-1 → nod-2 → nod-1 → smile（1 コマ 160ms）。smile 用（A-2 で端を listening から smile に。再生時は止まっているコマに置き換えるので動きは同じ）
    - `tilt`：smile → tilt-1 → smile、`tilt2` は tilt-2（かしげたコマを 0.8 秒保つ。120ms では「ぴくっ」としか見えない）。smile 用
    - `think`：think-1 → think-2 → think-1（120ms。考え中は think-1 で止め、これを 2 秒ごと＝まばたき）
    - `happy`：smile → happy-1 → happy-2 → happy-1 → smile（happy-2 だけ 160ms）。A-2 からは使っていない（present は `happy-up`）。残してある
    - `nod-down`：listening → nod-down-1 → nod-down-2 → nod-down-1 → listening（160ms）。listening 用
    - `tilt-down` / `tilt-down2`：listening → tilt-down-1 / tilt-down-2 → listening（[120, 800, 120]）。listening 用
    - `happy-up`：present → happy-up-1 → happy-up-2 → happy-up-1 → present（happy-up-2 だけ 160ms）。present（C2）用。終わったら `wave`
    - 従来の `blink` / `wave` / `smileDeep` はそのまま
  - **動かし方**：
    - 迎え（`smile`）と聞いている（`listening`）あいだ：6〜12 秒ごとに うなずき / かしげ / 逆かしげ のどれか（表情に合う列。直前と同じものは選ばない）。`listening` はまばたき（4〜7 秒）も。入力中・考え中・C2 のあいだ・別のコマ列の再生中・タブが隠れているときは見送る
    - 入力中（入力欄にフォーカスがあり文字がある）：すぐに 1 回、そのあと 3 秒ごとにうなずき（`listening` なので `nod-down`）
    - 考え中（「…」の吹き出し、「…考え中」の行、C2 の上の「…考えています」）：`think-1` で止め、2 秒ごとに `think`。文が届く・カードが出る・表情が変わると戻る
    - おすすめ（C2 が立ち上がる）：C2 の上のキャラクターで `happy-up` → `wave`（受付の窓のキャラクターは C2 の下に隠れているので、C2 の写しを動かす）。再生先は C2 の写しに固定し、`happy-up` のあいだに C2 を閉じた・「もう一度」を押したときは `wave` を流さない（受付の窓に手を振るコマが出ないように。REVIEW-2）
    - 「別のにする」（C2 の中の差し替え）：`happy-up` を 1 回（A-2 まではかしげ。present のかしげのコマが無く手が跳ぶので）
    - `prefers-reduced-motion` ではどれも動かさない。タブが隠れたら（`visibilitychange`）まばたき・考え中・入力中のタイマーとコマ列を止め、見えたら戻す（REVIEW-2）
    - **先読み**（REVIEW-2 P1）：`frames.json` を読んだあと、最初の表示を待ってから、**必要になる順に 3 本ずつ**読む。最初の表情（`smile`、上半身）の列 → C2 の列（`happy-up`・`wave`・`think`。C2 の写しはいつも**上半身**。PC の横長でも）→ 聞いているとき（`listening`。PC の横長は全身）の列（`nod-down`・`think`・`tilt-down`・`tilt-down2`・`blink`）。解像度（1x / @2x、WebP / PNG）は最初の顔が選んだものに合わせる。読めたコマは上半身／全身ごとに覚え、**全コマが読めた列だけ**その版で使う（その場で取りに行くと 120ms のコマに間に合わない）。列の端の表情（`smile` / `present` / `listening`）の画像もその版で読む。読んだ画像の参照は持ち続ける（手放すとメモリのキャッシュから落ち、Cloudflare Pages の既定 `max-age=0, must-revalidate` では差し替えのたびに確認の往復が入る）。`navigator.connection.saveData` のときはコマを読まない（呼吸だけ）
  - **重さ（11-07 A-2）**：21 枚 × 上半身／全身 × 1x／2x の WebP の合計は q72・alpha 70 のままでは 3.30MB。**q68・alpha 60・`preset: 'picture'`** で **2,981,530 バイト（2.98MB、上限 3.0MB）**、最初に読む `smile` の上半身（1x + 2x）は 67KB。PNG（fallback）は変えていない（既存の PNG はバイト単位で同じ）。WebP の合計はテスト（`tests/concierge-frames.test.ts`）で 3,000,000 バイト以下を確かめる
  - **重さ（A-1 の記録）**：WebP の合計（15 枚 × 上半身／全身 × 1x／2x）は q80・alpha 90 のままでは 3.3MB。コマだけ質を下げても 2.5MB に入らず、入れ替えの瞬間に画質が跳ねるので、**全部を q72・alpha 70** に（2x の顔の拡大で差は見えない）。合計 2,362,370 バイト（2.36MB）、最初に読む `smile` の上半身（1x + 2x）は 101KB → 73KB。PNG（fallback）は変えていない
- 名前と口調は `recommend/config.json` の `persona`。作家が直す。仮：名前は空（画面に出さない）、口調は丁寧で短い
- 画像は生成 AI（作家の絵は入れない）。`THIRD_PARTY.md` に生成手段を書く

### 3.5 おすすめは別の画面で（11-06 夜、作家「絵が選べたら別の画面に切り替わるほうが綺麗」）

会話の中にカードを出すのをやめ、**3 段**に分ける：

1. **読ませる**：AI の最後の文（おすすめの前置き）が出終わるまでは会話画面のまま。文が出終わったら、入力欄を消し、**1.6 秒**は何もしない（読む時間）
2. **考えている**：キャラクターが `listening` になり、会話の下に「…考えています」の小さな行（3 点の明滅）。**1.4 秒**。この間にカード用の絵を先読みする
3. **別の画面へ**：会話画面がゆっくり暗く沈み（0.5 秒）、**おすすめの画面**（C2）が紙白で立ち上がる。構成（上から）：キャラクター（上半身、小さめ。`present`）、ひとこと「これは、どうでしょう。」（`recommend/config.json` の `present_line`。作家が直す）、見出し「今日のあなたへの 1 点」、キャンバス（3.4 の登場：くるんくるん → ピカーン）、題名・寸法、理由の 1 文、使ったことば、3 択（この絵の中に入る / 別のにする / ギャラリー全体を見る）、下に小さく「会話に戻る」と「もう一度、話す」
- 「会話に戻る」は C2 を閉じて会話画面に戻る（会話は残っている。入力欄は「もう一度、話す」だけ）
- 「別のにする」は C2 の中で差し替え（3.4 の短い登場）。AI にもう 1 往復するときは、C2 の上に「…考えています」を出したまま待つ
- URL は変えない（`/` のまま。履歴に C2 を 1 つ積み、戻るボタンで会話に戻れる：`history.pushState`）
- ルールだけの版も同じ 3 段（「考えている」は 1.0 秒）
- `prefers-reduced-motion`：沈む・立ち上がるはフェードだけ、時間は同じ

### 3.6 おすすめの画面から、一気に絵の中へ（11-06 夜、作家）

- **ボタンの文言（11-06 夜、作家「『この絵の中に入る』は初めての人に意味が分からない。受け手の視点を大事に」）**：主ボタンは **「絵の世界をのぞく」**（en: Step into the painting）。直下に 1 行「色が動き出し、作家の言葉が流れます（約 2 分）」で、**何が起きるか・どれくらいか**を先に伝える（受け手が押す前に不安を持たないため）。作品ページの「入る」も同じ文言と 1 行。VR は「VR でのぞく」。戻ってきたあとの帯は「もう一度のぞく」
  - 検討した案：「絵について知る」（分かりやすいが、動く体験であることが伝わらない）、「絵の中へ」（詩的だが何が起きるか分からない）。「のぞく」は、短く、気軽に、絵の世界を見に行く感じが出る。「もっと知る」の意味は直下の 1 行が担う

- C2 の「この絵の中に入る」は、ページを移らず**その場で物語モードが始まる**（クリックのハンドラ内で体験を読み込む。音声の開始はこの操作の中）
- 体験が終わる（T5）か途中で閉じると、作品ページ `/w/<id>/?via=concierge&after=1` に着く。ここで「部屋で見る」「他の作品」が見える。帯は「絵の中から戻ってきました」＋「もう一度入る」「部屋で見る」「ギャラリー全体を見る」
- **「VR で入る」は VR の端末のときだけ**出す（Quest のブラウザで `immersive-vr` が使えるとき）。スマホや PC では出さない（作家「VR をつけているときだけそのモードが出るのがいい」）。C2 でも作品ページでも同じ条件

### 3.4 カードの登場（11-06 作家「キャンバスがくるんくるんくるん、ピカーン」）

- **くるんくるんくるん**：絵（キャンバス）が少し下から上がりながら Y 軸で 2 回転半して正面で止まる（1.1 秒、最初は速く最後にゆっくり。回っている間は 0.86 倍、止まるとき 1.0 倍。裏面は紙白）
- **ピカーン**：止まった瞬間、絵の後ろで淡い光が一度ふくらみ（0.45 秒）、絵の表面を細い光の帯が左上から右下へ 1 回走る（0.5 秒）。光の色は絵の主要色の明るい版。白のベタ光は使わない
- 題名・寸法・理由・3 つの選択は、止まったあと 0.15 秒ずつ遅れて下からふわっと
- `prefers-reduced-motion`：回転と光は出さず 0.3 秒のフェードだけ。「別のにする」の差し替えは短く（0.8 秒、1 回転半）
- CSS だけで作る（JS は class の付け外し）。音は付けない

### 3.7 扉の入場（11-08 作家「扉をカチャッと開けて、開いた先にこの人がいる」）

- 受付 `/` を最初に開いたとき、壁と 1 枚の扉を被せ、開いて通り抜けると本物の受付と案内役が見える。受付は裏で先に描画し、扉の終わりを待たない
- 時間（合計 2.1 秒）：取っ手が下がる 0.4〜0.56 秒 → 溜め → 右を蝶番に奥へ開く 0.75〜1.65 秒 → 枠ごと手前へ通り抜ける 1.6〜2.1 秒。タップ・クリック・キーですぐ飛ばせる（案内の文言は置かない）。音は鳴らさない
- 出さないとき：同じタブの 2 回目（sessionStorage）、`prefers-reduced-motion`、深いリンク（計測用の utm_ など以外のクエリ、hash）、裏のタブ、sessionStorage が使えないとき
- 壊さない作り：コードは `scripts/generate/door.js`。インラインの CSS とスクリプトで、既定は `display:none`。判定は `<main>` より前の同期スクリプトなので受付が先に見えない。画像が 800ms で揃わなければ開かずに受付を出す。スクリプトが止まっても CSS の `door-bail`（3.8 秒）だけで消える。受付の DOM には触らない。`aria-hidden` で、終わったら DOM から取り除く
- 開口の位置：受付の案内役は幅によらず中央の上にあるので、開口は中央で、上端を案内役の窓の高さ（`.cg-host`、上から 60px）に合わせる
- 画像は `public/concierge/door/`（壁、枠、扉の板、座金、取っ手。Codex の画像生成で作り切り抜き、webp 合計 66KB）。参照に使ったのはキャラクターの画像だけ。受付の背景（`wall-*`）は絵が合成されているので使っていない

## 5. 配線：作品のことば → カタログ → AI

受付が「あなたへの 1 点」を選べるのは、各作品に**ことば**があるから。鎖は次のとおり。どこか 1 つでも空だと、AI は色の軸だけで選ぶことになる。

```
docs/WORKS_VOICE.md           作家の語り（11-06 口述。原典）
        ↓ 作家のことばで整える（下書き → 作家が直す）
works/<id>/work.json          messages（作家の声、3〜5 行）、messages_en、moods（気分の言葉、3〜5 語）、moods.fit（向く人・時間、1 行）、note
recommend/voice.json          voice（作家の語り、一人称 2〜4 文）、scene（この絵のある暮らし、1 文）、fits（こんな人・こんなときに、3〜5 つ。文で）← 11-06 夜「ロジックが冷たい」への対応。タグの羅列ではなく話し言葉
        ↓ npm run generate
works/<id>/generated/space.json   messages（10 言語）、story
public/catalog.json               id、title、size、availability、palette、axes（warmth / brightness / energy）、moods、fit、messages、story
        ↓ Function が読む（10 分キャッシュ）
system プロンプト（functions/_lib/prompt.js の catalogText）
        ↓
ツール recommend_work（id は enum、reason、matched_moods）
```

V1 でやること（E-4）：

- **6 作品すべてに `moods` と `messages` を置く**。金沢展の 5 点は `docs/WORKS_VOICE.md` の語りから、作家の一人称で 3〜5 行に整える（先頭に `（下書き。作家が書き直す）`は付けない。語りが作家本人のものだから。ただし `note` に「11-06 の口述から整えた。作家が直す」と書く）。英語は `messages_en` に
- **`moods`**：各作品 3〜5 語。語りの中の言葉を使う（例：New Chapter「新しい章」「元気が出る黄色」「半立体のドット」）
- **`moods.fit`**（ja/en、1 行）：どんな人・どんな時間に向くか（例：「新しいことを始める朝に」）
- `catalogText` に `fit`・`voice`・`scene`・`fits` の行を足す。system の理由の決まりは「まずその人が話したことを 1 つ拾って自分の言葉で返し、そのあとに絵の何がそれに応えるかを作家の語りから 1 つだけ、話し言葉で。ことばを並べない。『〜だから。』の型にしない」（11-06 夜）。カードの「ことば」の行は出さない（データは残す）
- `recommend_work` の入力に `matched_moods`（文字列の配列。選んだ作品の moods から 1〜3 語）を足す（strict）。カードの理由の下に小さく出す
- 翻訳（8 言語）は作家のキー付き `generate` で後から。V1 は ja / en

## 9. 受け入れ条件（V1）

10. C2 の「この絵の中に入る」でその場で物語モードが始まり、終わると作品ページに着いて「部屋で見る」が見える。「VR で入る」は VR 端末でだけ出る
